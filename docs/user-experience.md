# 阅读、核对与用量

本版面向普通个人用户。新任务提供分级质量与有限自动改进，首次默认低档；不自动更换模型、思考模式或上下文配置。

## 连接模型与导入资料

「文字模型」负责问答、摘要和学习内容；「资料导入」管理专用视觉模型和图片处理优先级；「播客语音」是可选能力；本地工具与检索信息在「高级与诊断」。配置名称可以留空，保存时采用模型名。

图片处理默认依次尝试 VLM、具有视觉能力的 MAIN、本地 OCR，成功后停止。暂停 VLM 不代表关闭整个图片处理；没有启用或未声明视觉能力的模型会被跳过。OCR 的引擎可用性在导入时确定，不能把预览当作保证。处理顺序编辑不改变启用开关。

上传默认继承全局方式。只有「仅修改本次」会展开覆盖选项，不写回全局设置，不重新处理历史资料。模型识图可能消耗 token；OCR 不调用模型。纯图片资料如果没有提取出文字，会无法用于检索，请查看资料上的具体提示。

## 什么时候调整高级参数

- **上下文窗口**：单次请求的资料、指令和输出容量。它不是固定扣费量，也不是整项任务累计消耗。优先采用服务报告的实际值；能力未知时本应用回退为 4096 tokens。仅在确认服务真实运行容量与识别值不符时手动覆盖，不把理论最大值直接用于本地运行。
- **最大输出**：单次回复上限，部分模型的思考也占此额度。生成或审校输出被截断时检查它；调大可能增加耗时与消耗，并压缩输入空间。
- **思考模式**：本版 Ollama 集成继续固定请求 `think=false`，界面不提供无效切换。已识别服务协议的兼容接口可请求开关；未知服务保留已保存配置但不假定支持。参数被拒绝后可能回退到服务默认行为，用量详情显示实际发送的每次参数，不能视为服务已采纳的证明。
- **温度与档位**：高级选项；温度覆盖整个 Provider 的任务默认设置。档位影响批次安排，不代表质量认证。所有学习档位都尝试一次原文抽查。

“恢复任务默认参数”只清除温度、思考、推理强度、窗口、最大输出和学习档位覆盖；模型、语音配置和上下文策略保持原值。容量表中的策略资格仍按实际配置判断，未获得资格不会自动启用均衡策略。

## 理解检查状态

“生成完成”与“事实支持”是不同维度。核查计数指获得有效审校结论的内容单元，支持和不支持均算已核查；不代表正确率。

- 已核对 4/6 项：其余 2 项尚未获得有效结论。
- 尚未完成原文核查（0/6）：可能是预算不足、模型服务失败或审校回复不可验证。新结果会记录已知原因；历史记录可能无法追溯。
- 原文核查不适用：例如资料不足说明或原文摘录，没有进行额外事实核查。
- 本地结构、引用标记、播客连贯性与音频验收各有适用范围，均不能替代事实核对。

新任务在正文下显示自动评分；用量、覆盖和旧核查信息收在「查看详情」。不再要求普通用户填写重新审校预算。旧的独立审校 API 保留供兼容使用，不改写历史产物。

## 用量和上限

任务入口的本地估算使用实际资料统计、执行规划器和题卡批次规则；保守与均衡策略分别标注。预计调用数不等于实际调用数，长任务的恢复、章节与选材情况会影响它。选材输入估算不含每次重复发送的完整累计成本，不是账单。

“本次用量”展示服务返回的已知输入和输出；推理属于输出的子集，缓存属于输入的子集，不重复相加。服务未单列推理或缓存时，显示的合计不证明它们没有发生。

逐次请求记录包括兼容参数重试、技术恢复、失败、超时与取消；没有返回完整计量的请求标为未知，并保留预算预留。已知 token、输入估算、执行预留分别展示，未知消耗不伪装成零。语音的尝试输入字符数、可测量音频秒数及状态另列，不折算为 token 或货币费用。详情最多展示最近 100 次请求参数，总计覆盖全部记录。

可选的 `token_limit` 为 1024–4194304 的整数，留空使用包含质量轮次的默认任务预算。设置后，每次真实模型请求前预留保守输入估算与最大输出；生成阶段保留 25% 给审校，未知消耗不会退还。同一后台任务重启续跑继承已占用额度；重用已有内容不重复记成新调用。上限过低可能不能启动生成或审校，结果会保留可用部分。该上限不限制 TTS/ASR，也不能保证远端账单金额。

原生成结果的用量不混入主动重新审校，后者随独立报告展示。资料库累计用量按需读取，包括失败任务与主动重新审校；不包含旧版本从未记录的消耗。删除任务记录不清除已记录的消耗，删除资料库会级联删除其资料库用量详情和审校报告；v0.4.12 的独立周额度流水保留。不持久保存提示词、响应正文或凭据到用量表。

## API

- `POST /api/notebooks/{id}/task-preview`：`kind`、`source_ids`、`question`、`count`、`minutes` 和可选 `token_limit`；只在本地估算。
- 问答、摘要、测验、闪卡与播客提交体接受可选 `token_limit`。
- `GET /api/notebooks/{id}/usage`、`GET /api/jobs/{id}/usage`：计量、未知项、阶段与语音请求明细。
- 问答的 `metadata.usage`、产物的 `payload.usage` 和任务详情的 `usage` 提供相应统计；保留原 `context_usage` 字段。
- `POST /api/reviews`：`target_type=artifact|message`、`target_id` 和可选 `token_limit`，返回独立报告及用量。
- `GET /api/reviews?target_type=...&target_id=...`：读取最近 20 份独立报告，不触发生成。
- 质量报告新增 `review_status`、`reason_code`、`reason`；原 `level`、计数及问题字段保留。

## 升级与回退

v0.4.11 需要一起更新前后端，数据库自动增量迁移到 v7。没有新增依赖或全局配置字段。备份数据库后重启后端；重建前端前确认后端代码已同步。历史产物不要求重新生成，缺失信息不伪造回填。服务重启把中断运行与未结束请求标为不确定，同一任务恢复时仍计算旧预留。

回退前保存当前数据库备份，旧代码可忽略新增表，不用旧数据库覆盖新产生的资料与学习记录。Windows 操作遵循 [部署手册](windows-deployment.md)。

## 验收与质量对照

离线测试：`.venv/bin/pytest -q`。在 `frontend/` 运行 `corepack pnpm lint` 与 `corepack pnpm build`。也可把 Vite 构建输出到临时目录，避免影响现用静态页面。

隔离浏览器检查：用静态服务器提供构建目录，再运行 `SREAD_BROWSER_FIXTURES_ONLY=1 SREAD_BROWSER_BASE_URL=http://127.0.0.1:20831 .venv/bin/python tests/browser_smoke.py`。全部 API 请求被夹具拦截，覆盖桌面、手机、键盘、默认继承、审校提示、用量和示例，不向现用服务上传资料或调用 Provider。

人工新用户验收目标：至少 4/5 位参与者在提供有效连接信息后，无帮助完成首次生成、打开引用、找到用量，并正确解释“尚未核查”。这属于待开展的用户研究，不以自动浏览器测试代替。

质量收益需通过 [综合功能实测](podcast-evaluation.md#4-综合功能实测) 使用显式样本及服务地址验证。固定资料修订、模型和配置；保存系统输出及同模型单次直接提示的基线，分别统计请求用量、耗时、有效完成、事实支持和遗漏。对照样本至少包含短文、跨文档冲突、条件/否定表述、长文与表格；人工盲评不能把生成成功或引用存在算作事实正确。不将一次自审称为独立模型裁决，也不预设本系统优于官网聊天。


## 每周额度（v0.4.12）

不配置即可看到每周 1,000,000 tokens、500 次文字/视觉请求的参考进度。默认只提醒，可改为停止新请求；正整数设置额度，留空关闭单项。Provider 额外额度默认不启用。全局及 Provider 分别设置提醒/停止，任何适用的停止限制不足都会拒绝请求；单任务上限仍然有效。

这是本应用的初始参考值，不是厂商默认赠送额度。厂商的 RPM/TPM 是速率限制，不能直接换算为每周消费预算。本应用没有用户账号隔离，整个实例共用额度；同一服务的多个 Provider 配置分别统计，不按 API Key 合并。Ollama 计入使用量但不等同于远端付费。

每周一零点按预算时区切换周期。首次打开页面采用浏览器 IANA 时区，之后其他设备读取同一时区；未初始化时后端使用 UTC。修改时区会重新划分本周范围，不删除消费记录。跨周完成的请求归入发送时所在周期。Windows 使用随依赖安装的 tzdata。

输入加输出为已知 token，缓存与推理不重复累计。执行中、超时、取消及计量缺失保留估算输入与最大输出的预留，纹理区不是实际扣费量。停止模式在每次请求前以已知量加预留检查，因此可能在已知消耗未满时停止；不承诺远端账单绝不超额。额度拒绝不会发送请求、不会增加调用次数，也不会自动重试。已有可用内容会保留，核查或任务提示说明额度不足。调整额度后需主动重试任务。

生成、视觉处理、额外审校、兼容重试及文字/视觉深度验证都会计数；模型列表、健康查询、OCR、向量计算、TTS/ASR 不计入这两项额度。未保存的连接测试只计入全局。删除资料库、任务、Provider 不删除独立额度流水；流水不存正文、提示词、响应或密钥。此前已删除或从未计量的历史无法恢复。

API：`GET/PUT /api/settings/usage-budget` 管理 `timezone`、`global_limit` 和以 Provider ID 为键的 `providers`，额度含可为 null 的 `tokens`、`calls` 以及 `mode=warn|block`。PUT 的 `initialize_only=true` 仅首次设置时区，不覆盖已保存额度。`GET /api/usage/weekly` 返回周期、已知及待确认用量、剩余估算和 Provider 明细。任务预估附带 `weekly_budget`。直接请求遇到拦截返回 HTTP 409 和 `quota_exhausted`、范围、指标、重置时间；已保留结果通过 warnings/审校说明提示。

v8 增量迁移幂等导入已有请求记录，不要求重跑历史任务。旧的资料库用量详情仍随资料库删除，全局额度流水独立保留。升级前备份数据库并同步前后端；回退代码不会删除新增流水表，但旧代码不再执行每周限制。


## 界面与键盘操作

MAIN 高级参数中的「恢复任务默认参数」清除当前表单的任务参数覆盖，点击后仍需「验证并保存」才生效。按钮采用与深色界面一致的高对比度样式。

手机聊天区的「本次范围与用量」在独立弹窗中展示，关闭、重新打开或切换屏幕尺寸均保留本次上限；桌面及生成设置弹窗仍可原位展开。顶部用量条在手机上使用紧凑数字，精确数量、待确认部分和限制说明可在「本周用量」中查看。

额度设置区分已保存值和编辑草稿。修改后显示「有未保存修改」，保存中暂时禁用编辑；失败时保留草稿供重试。关闭面板不会丢弃本页草稿，刷新页面会重新读取服务端配置。Provider 额度开关与名称同行，点击名称也可切换。

弹窗支持 Tab / Shift+Tab 循环，折叠标题可用 Enter / 空格展开；隐藏内容不会占据焦点。Escape 关闭最上层弹窗并将焦点还给入口，引用弹窗关闭后返回原引用按钮。


## 分级质量与自动改进（数据库 v9）

问答、摘要、测验、闪卡、播客脚本分别记住浏览器的质量选择，首次均为低。结果页临时降档不修改长期偏好；浏览器禁用存储时仅在当前页面记住。直接在对话中要求“三个核心要点”或“双人播客脚本”会得到文字回答，完整学习产物通过「学习与输出」创建。

| 质量 | 目标分 | 自动改进上限，不含首版 | 原文重点采样上限 |
| --- | --- | --- | --- |
| 低 | 60 | 1 | 4 段 |
| 中 | 75 | 1 | 8 段 |
| 高 | 85 | 2 | 16 段 |
| 极致 | 92 | 3 | 32 段 |

首版保存后立即可读，每版由提交时固定的 MAIN 配置独立评分，替代旧产品终审调用。评分统一采用资料忠实度40、要求完成度30、结构连贯20、表达清晰10，服务端验证分项并求和。评分是抽样辅助判断，不是事实正确率；窗口限制与实际采样保存在覆盖信息中。无效评分显示「暂未评分」，不会填零分。表达形式、主持人篇幅比例等只是质量建议；明确未完成要求、伪造引用或确认的事实矛盾不能达标。

未达目标时自动依据评分建议改进，达到目标或次数上限即停止。最高分版本保留，同分保留较早版本，未评分版本不替换已评分版本。结束后可以「保持当前结果」、追加1–5次改进或降低档位；当前得分已满足新档位时直接采用，不发请求。评分服务失败时，追加操作优先重新评分已有内容。显式单任务用量上限覆盖首版、评分和所有自动/手动追加请求；不会因重试重置。默认总预算包含档位允许的轮次，主动追加时只扩展默认预算；每周停止限制始终有效。TTS/ASR 仍单独计量。

测验、闪卡与脚本使用独立候选版本。正在答题、复习或播放的版本保持稳定，界面提供查看改进版本的入口。播客只将最终选定脚本交给音频合成，后续选定脚本未变化时不重新合成。音频不可用仍保留脚本。资料修订变化时停止改进，已有内容不丢弃。

新接口：`POST /api/notebooks/{id}/chat-runs` 返回202及任务、消息和对话引用；`GET /api/quality-runs/{id}` 查询状态和版本；`POST /api/quality-runs/{id}/actions` 接收 `action=keep|retry|lower`、`base_version`、`request_id`、`attempts=1..5` 及可选 `quality_level`。相同 request_id 不重复排队，旧同步 chat 接口保持原语义。公开质量状态不包含候选正文，测验评分建议与答案不外泄。

升级须同步前后端、备份数据库并在空闲时重启。v9 增量创建 quality_runs/quality_versions，资料库删除时级联清理；不新增全局配置。历史产物不补造分数，升级前已排队任务维持旧语义。重启保留版本、次数和消费；进程中断时正在等待的请求消费未知，不自动重发，用户可从已保存版本继续。回退旧代码会失去新流程入口；恢复完整旧行为应使用升级前数据库备份，避免旧工作器执行新任务。


## 阅读界面精修

工作台保留深色青黄主题。正文与摘要统一为 16px，表格和代码在自己的容器中横向滚动；回答中的标题、加粗、有序列表与代码按 Markdown 排版。有效引用仍打开原文抽屉，未知引用保持文本，代码中的引用标记不转换为按钮。原始 HTML 不执行，回答中的远程图片只显示替代文字；原有引用原图仍通过本地资料接口读取。

首次使用时，主阅读区提供当前步骤及下一步操作；配置、资料库或可用资料未就绪时收起空输入区。生成内容后，指南从聊天标题旁的「使用指南」打开。正常聊天将输入与发送、质量与范围各排成一行。顶部用量使用紧凑摘要；「含预留」表示还存在执行中预留或待确认用量，完整数值、未知项及阈值说明在「本周用量」面板中。手机短高度视口暂时收起顶部用量条和聊天标题，给内容和输入留出空间。

中文输入法合成期间的 Enter 只确认候选词，结束合成后 Enter 发送，Shift+Enter 换行。载入对话或主动发送时显示最新内容；向上阅读后，新结果不抢走位置，可点击「回到最新」。阅读区域或结果高度改变时，仅在原本跟随底部的情况下继续跟随。

结果与设置采用固定标题、独立滚动正文和固定操作区。桌面生成表单居中显示，手机全屏显示。Escape 关闭最上层面板，Tab / Shift+Tab 循环及关闭后的焦点返回继续有效；模型设置仍需确认放弃未保存内容，用量草稿仍在本页保留。

侧栏显示最近六份成果，「全部成果」可按名称及类型筛选当前资料库的全部已有成果。打开结果后关闭可返回筛选列表；搜索、筛选和阅读不触发重新生成。资料行提供键盘可展开的「资料详情」，显示完整文件名与错误。失败资料的错误说明不会随禁用勾选一起变暗，手机资料库卡片保留清理失败原因及重试入口。

本次仅调整前端，新增锁定的 react-markdown 10.1.0 和 remark-gfm 4.0.1 依赖，无数据库、配置或 API 迁移。更新时在 frontend 目录安装锁文件依赖并重建前端；旧结果无需重跑。

隔离浏览器回归新增首次使用、320px 阅读空间、Markdown 与引用、输入法合成、保留滚动位置、长面板操作区、八份以上成果和手机错误信息检查。运行 `SREAD_BROWSER_FIXTURES_ONLY=1 .venv/bin/python tests/browser_smoke.py`，所有业务 API 均被夹具拦截。真实手机键盘和 Safari 仍应在目标设备上验收。

## 状态、操作成本与成果复用

- 配置保存完成后同步刷新模型、角色和健康状态；刷新失败提供单独重试，不要求重新保存。表单失败保留草稿。文字模型入门步骤以健康检查为准。
- 质量档位显示为「快速、均衡、精细、更多核查」，内部仍是 `low/medium/high/extreme`，默认快速，阈值、轮数和预算不变。「达到本档生成目标」不表示事实正确率；资料覆盖和语音验收各自展示。
- 设置按文字模型、资料导入、播客语音、用量与额度、高级与诊断组织。图片预设立即保存，只影响新上传；语音高级参数默认折叠。单次容量、任务预算与周额度用途不同。
- 点击「向资料提问 ▾」打开历史对话和资料范围。对话按时间排序，可搜索标题或日期；记住每个资料库最后打开的对话。未发送草稿仅在当前页面内存保留，刷新页面不会恢复草稿。
- 打开历史对话保持当前勾选资料。新消息保存提交时的资料 ID、修订和名称；恢复历史范围先列出可用、删除或修订变化的资料，只在显式应用后更新。旧消息缺少记录时标为未知。范围批量保存为原子操作。
- 回答可复制正文与引用。固定修订原件可打开或下载，PDF 支持页码；旧原件不可用时引用摘录仍保留。
- 摘要支持可选侧重点、篇幅和语言，默认不变；偏好传递到初稿、评分和改进，不能绕过证据与容量限制。复制与 Markdown 导出针对正在查看的版本，不额外调用模型。
- 测验提供题号导航、未答/正确/待复习标记和跳到未答题；答后解析下方可继续下一题。答案仍由提交作答接口返回。
- 「学习与输出 → 复习安排」查看当前或全部资料库的到期、新卡、下次到期与暂停卡。提醒只在应用内显示，打开、回到窗口、复习变更和下次到期时刷新，不发系统通知。暂停保留 FSRS 状态，支持即时撤销及稍后恢复。
- 仅脚本播客的章节定位文本，文本轮次不伪装成播放按钮。补音频先显示当前语音配置与主持人；提交后绑定快照。音频完成不会自动切换正在阅读/播放的版本，选择版本后时间轴、播放器和下载同步。

### 数据与验证范围

数据库 v10 新增独立音频版本关联表。首次迁移前在数据库旁创建 `*.pre-v10.bak`，不重生成成果、不重建索引、不清空周用量。旧会话、旧学习记录与原始音频继续可用。

浏览器验证使用 Python Playwright 和本机 Chromium（此环境无 Browser 插件），所有业务接口均由合成 fixture 拦截；不上传真实资料，不调用外部模型。人工五人可用性测试与真实服务质量、耗时验收需要另行安排，自动化回归不代替这些结论。
